Notulen Keputusan Arsitektur Keamanan

Subjek: Standarisasi manajemen sesi dan autentikasi pengguna LDAP UY · Penyusun: Arman Dava Wicaksono (1402024010) · Kelompok: Sprout Apex · Dasar: audit keamanan sesi dan rubrik Mode A

Berdasarkan audit pada AuthController, config/session.php, config/ldap.php, bootstrap/app.php, dan routes/web.php, ditetapkan empat keputusan arsitektur berikut. Seluruh keputusan telah diterapkan pada kode dan diuji otomatis.

1. Data yang disimpan dan dilarang disimpan di sesi setelah login LDAP

Setelah Auth::attempt() memverifikasi kredensial ke LDAP berhasil, ID sesi lama wajib dibuang dan diganti ID baru melalui $request->session()->regenerate() sebelum respons redirect dikirim. Sesi server hanya menyimpan identitas minimal:

  • auth_identity.user_id — primary key pengguna untuk guard Laravel;
  • auth_identity.nama, role, serta npm/nidn — identitas tampilan dan otorisasi;
  • auth_login_at — timestamp login pertama (dasar absolute timeout, tidak pernah diperpanjang);
  • auth_last_activity — timestamp aktivitas terakhir (dasar idle timeout);
  • _token — token CSRF bawaan Laravel.

Dilarang keras disimpan: password dalam bentuk apa pun (plaintext maupun hash), password/kredensial bind LDAP, serta atribut privat direktori (userPassword, mail alternatif, telephoneNumber). Larangan ditegakkan berlapis: (a) sync_passwords=false pada provider LDAP; (b) storeMinimalSessionIdentity() hanya menulis kunci di atas; (c) middleware memanggil forget() terhadap kunci sensitif (password, credentials, ldap_password, bind_password, userpassword, dan sejenisnya) pada setiap request; (d) 'enabled' => env('LDAP_LOGGING', false) mematikan logging LDAP agar kredensial tidak bocor ke log.

2. Batas waktu idle 30 menit dan absolut 8 jam

Middleware EnforceSessionTimeout — terdaftar pada grup web di bootstrap/app.php — memeriksa dua ambang pada setiap request terautentikasi: idle timeout 30 menit (SESSION_LIFETIME=30) dengan ($now - auth_last_activity) >= 30 × 60; dan absolute timeout 8 jam (SESSION_ABSOLUTE_LIFETIME=480) dengan ($now - auth_login_at) >= 480 × 60 yang tidak pernah diperpanjang oleh aktivitas.

Alasan kontekstual: 30 menit adalah durasi wajar bagi pengguna yang meninggalkan komputer bersama di laboratorium, ruang tata usaha, atau perpustakaan tanpa logout; akun tidak dibiarkan terbuka berjam-jam hanya karena satu tab terlupa. Batas absolut 8 jam setara satu shift kerja atau satu hari perkuliahan aktif, sehingga pengguna yang terus bekerja tetap dipaksa autentikasi ulang sekali per hari dan hak aksesnya diverifikasi kembali ke direktori pusat LDAP. Respons pemaksaan logout: redirect 302 ke /login untuk request web, atau 401 JSON untuk API/AJAX.

3. Alur logout di server dan peramban

  1. Auth::logout() — status autentikasi guard web dicabut dan remember_token dihapus.
  2. $request->session()->invalidate() — seluruh data sesi server dihancurkan dan ID sesi dimigrasikan.
  3. $request->session()->regenerateToken() — token CSRF lama diganti sehingga replay CSRF pasca-logout ditolak.
  4. Cookie::queue(Cookie::forget(config('session.cookie'), config('session.path'), config('session.domain'))) — respons membawa Set-Cookie bernilai kosong dengan expires masa lampau; peramban menghapus cookie seketika.
  5. Redirect 302 ke /login.

Cookie diantrekan (bukan withCookie) agar header penghapusan ditulis setelah StartSession menulis cookie sesi baru dan tidak tertimpa. Cookie lama yang sempat disalin penyerang tidak dapat dipakai ulang karena sesinya sudah tidak ada di server; request berikutnya dibuatkan sesi baru tanpa autentikasi lalu dialihkan ke /login.

4. Atribut cookie sesi dan alasan teknis

AtributNilaiPerlindungan
HttpOnlytrue (SESSION_HTTP_ONLY=true)Cookie tidak dapat dibaca/dimanipulasi document.cookie, sehingga pencurian sesi lewat XSS tidak mungkin dari JavaScript.
SameSiteLax (SESSION_SAME_SITE=lax)Cookie tidak dikirim pada request lintas situs berisiko (POST/iframe), mempersempit CSRF; Lax tetap mengizinkan navigasi tautan biasa.
SecureDinamis via SESSION_SECURE_COOKIE; default true saat APP_ENV=productionCookie hanya dikirim lewat HTTPS/TLS sehingga tidak dapat disadap atau dibajak pada Man-in-the-Middle.
Path/Domain/ dan nullMembatasi cakupan cookie ke aplikasi, bukan seluruh domain kampus.

Kombinasi ketiganya memberi pertahanan berlapis: XSS tidak bisa mencuri cookie, CSRF tidak bisa memanfaatkan cookie lintas situs, dan MitM tidak bisa menyadap cookie di jaringan.
